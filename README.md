# StreamLab MVP

Мінімальний локальний застосунок для двох дій:

1. завантажити один або декілька готових відеофайлів;
2. вибрати файл і запустити його циклічну RTMPS-трансляцію на YouTube через FFmpeg.

Це свідомо вузький MVP із входом OWNER. Тут ще немає черги, транскодування бібліотеки,
автоматичного reconnect, промоматеріалів, Telegram і статистики YouTube.

## Що потрібно

- Node.js 22.13 або новіший;
- FFmpeg у `PATH`, або Docker Desktop;
- RTMPS URL та stream key із YouTube Live Control Room;
- стабільний upload приблизно 12–15 Мбіт/с для профілю 1080p30.

## Налаштування доступу OWNER

Скопіюйте `.env.example` у `.env`, придумайте пароль від 12 символів і згенеруйте
хеш пароля та секрет сесії. Сам пароль у `.env` не зберігається:

```powershell
$env:OWNER_PASSWORD="ваш-надійний-пароль"
npm run auth:setup
```

Перенесіть усі три рядки з результату до `.env`, а потім приберіть пароль із
поточного термінала. Не видаляйте одинарні лапки навколо згенерованих значень —
вони не дають Docker Compose інтерпретувати символи `$` всередині хешу:

```powershell
Remove-Item Env:OWNER_PASSWORD
```

`OWNER_USERNAME` за замовчуванням має значення `owner`. Не додавайте `.env` до Git.

Якщо OWNER-доступ уже налаштований у попередній версії, згенеруйте лише новий ключ
шифрування стріму й додайте виведений рядок до `.env`:

```powershell
npm run stream:secret --silent
```

## Найпростіший запуск через Docker

Після налаштування `.env` запустіть обидва сервіси:

```powershell
docker compose up -d --build --wait
```

Відкрийте `http://127.0.0.1:3000`. Назовні публікується лише вебпорт `3000`.
Next.js передає `/api` до медіасервера через внутрішню Docker-мережу, тому порт
`8788` із хоста недоступний.

### Продакшн (обидва сервіси в Docker)

`compose.yaml` запускає Next.js і медіасервер окремими непривілейованими процесами.
На сервері створіть `stream-lab/.env` з `OWNER_PASSWORD_HASH`, `SESSION_SECRET`,
`STREAM_CONFIG_SECRET` та іншими значеннями з `.env.example`. Каталог `data/`
повинен бути доступним для запису користувачу з UID 1000.

```powershell
docker compose up -d --wait
```

Панель буде доступна за `http://<SERVER_IP>:3000`. На цьому етапі HTTPS свідомо
не налаштований, тому використовуйте довірену мережу і не передавайте пароль чи
stream key через публічні незахищені мережі.

CI/CD спочатку запускає тести, lint і production-збірку, потім публікує SHA-образи
та розгортає їх із healthcheck і rollback. Для деплою потрібні GitHub Secrets
`SERVER_HOST`, `SERVER_USER` і `SERVER_PASSWORD`.

## Запуск із локальним FFmpeg

Якщо FFmpeg не доданий до `PATH`, задайте абсолютний `FFMPEG_PATH` у `.env`.

```powershell
npm install
npm run dev
```

Команда одночасно запустить вебінтерфейс на порту `5173` і медіасервер на
порту `8788`.

## Як запустити тестовий ефір

1. У YouTube Studio створіть трансляцію через encoder. Для першого тесту оберіть
   доступ «За посиланням».
2. У StreamLab завантажте MP4, MOV, MKV, WEBM або M4V.
3. Виберіть готовий файл.
4. Вставте RTMPS Server URL і Stream key.
5. Натисніть «Запустити трансляцію» та перевірте появу сигналу в YouTube Live
   Control Room.

Stream key не записується до каталогу відео й не повертається через API. Усі операції
з відео та трансляцією вимагають OWNER-сесію та CSRF-токен. Сесія підписана,
зберігається в `HttpOnly` cookie й автоматично завершується через 12 годин.

Під час активної трансляції вибране відео та stream key зберігаються в `data/`
лише у зашифрованому AES-256-GCM файлі. Після падіння FFmpeg або перезапуску
контейнера ефір відновлюється автоматично з експоненційною затримкою до 5 хвилин.
Ручна кнопка «Зупинити» видаляє зашифровану конфігурацію та вимикає автовідновлення.

## Перевірка

```powershell
npm test
npm run build
```

Завантажені файли та локальний каталог зберігаються у `data/`, який виключений із Git.
